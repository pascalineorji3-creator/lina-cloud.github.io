01 · Overview

Turning vague “AI writing” signals into something people can inspect.

TellTale is a browser-based experiment exploring how linguistic patterns commonly associated with generic AI-generated writing can be presented as an interactive editorial experience.

Instead of presenting the user with a simple “AI” or “human” verdict, the interface highlights individual phrases and connects them to short explanatory notes.

The central product idea is simple: show the pattern, explain the signal, and let the user make the final judgement.

02 · The Product Idea

Detection as an editorial conversation.

Many AI-writing discussions focus on whether a detector can produce a definitive classification. TellTale takes a different interface approach.

The experience behaves more like an editor marking up a manuscript. Potentially generic phrases are underlined, and corresponding margin notes explain the type of pattern that triggered the highlight.

Visible evidence

Potential signals are highlighted directly inside the sample text instead of being hidden behind a single score.

Explanatory notes

Each highlighted phrase is paired with a short explanation, turning the result into something a user can inspect.

Interactive markup

Hovering or focusing a highlighted phrase connects it to its corresponding editorial note.

User-controlled testing

Users can open the editor, paste their own paragraph, and run the current local pattern analysis in the browser.

03 · Linguistic Signals

The current implementation uses pattern-based signals.

The live implementation contains a collection of JavaScript regular expressions designed to identify recurring phrases and constructions often associated with generic AI-style writing.

Stiff transitions
Terms such as “furthermore,” “moreover,” and “in conclusion” are treated as potential signals of formulaic prose.
Generic framing
Phrases such as “in today's fast-paced world” and “it is important to note that” are flagged as generic openings or framing devices.
Vague language
Expressions such as “wide range of,” “robust,” and “holistic” can be flagged when they provide broad meaning without much concrete information.
AI-associated phrasing
Terms and constructions including “leverage,” “delve into,” “unlock,” “seamless,” and “game-changing” are included in the current rule set.
04 · How The Analysis Works

Small rules, visible reasoning.

The current implementation deliberately keeps the analysis self-contained. There is no external API call in the browser analysis currently used by the live interface.

When a user submits text, JavaScript scans it against the project's predefined pattern rules. Matching phrases are collected, positioned in the original text, and displayed as interactive annotations.

const { score, flags } = analyzeLocally(text); render(text, flags, score); editorStatus.textContent = flags.length ? "Marked up. Hover a circle or a note to see the connection." : "Nothing jumped out. That's a good sign.";

The current score is derived from the number of detected patterns relative to text length. It is therefore an experimental density signal, not a probability that a text was written by AI.

05 · Interaction Design

The interface is part of the experiment.

TellTale was designed around the idea that an analytical tool does not have to feel like a dashboard.

The live interface uses a dark “desk” environment, a paper-like document, handwritten-style annotations, red editorial markings, and connecting lines between flagged text and margin notes.

Editorial metaphor

The paper and handwritten markup create a familiar mental model: someone is reviewing a piece of writing.

Progressive interaction

The user can first inspect the example, then open the editor when they are ready to test their own text.

Responsive layout

The desktop experience uses margin annotations and leader lines, while the layout adapts for smaller screens.

Accessibility considerations

Interactive flags and notes support keyboard focus, and visible focus states are included in the interface styling.

06 · Privacy & Processing

The current user analysis stays in the browser.

The current “Try your own paragraph” implementation performs its analysis locally with JavaScript.

The interface explicitly communicates that the submitted text is not sent anywhere during this local analysis flow. The project therefore provides a useful privacy-oriented interaction model while experimenting with the detection concept.

Current implementation: local pattern matching, client-side scoring, and browser-rendered markup. No external network request is required for the current analysis.

08 · Limitations

What TellTale does not claim.

TellTale is intentionally presented as an experimental writing pattern explorer rather than a scientifically validated AI detector.

The current rule-based approach can identify phrases that match its predefined patterns, but a matching phrase does not prove that a language model wrote the text.

Human writers can naturally use the same vocabulary, while AI systems can produce writing that avoids these particular patterns. The score should therefore be treated as an exploratory signal, not a definitive classification.

The product itself communicates this limitation: “It isn't a lie detector.” The circles are intended as a second opinion, not a verdict.

09 · Product Thinking

The interesting part is not just the detector.

The project explores a broader product question: How can an AI-related analytical tool expose its reasoning instead of asking users to blindly trust a score?

That led to several design decisions: visible evidence, contextual explanations, local processing, an editorial metaphor, and an explicit warning against treating the result as proof.

The result is a small but focused experiment combining front-end engineering, AI concepts, linguistic pattern exploration, UX design, and responsible product communication.

10 · Current Status

A working prototype with room to evolve.

Current state: Working web prototype

The live project contains the interactive editorial interface, local pattern analysis, user text testing, phrase highlighting, margin explanations, scoring, responsive behavior, and Netlify deployment.

Future development could explore broader linguistic features, stronger evaluation methodology, larger test sets, and additional analysis approaches. Those are future directions rather than capabilities claimed by the current implementation.
